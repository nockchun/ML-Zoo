## Application Level Harness
요구사항을 제대로 써서 요청.
```prompt
[목표]
재고와 품절 기능을 만들어 주세요.

[재고 데이터]
src/menu.js 의 각 메뉴에 stock 필드 추가:
아메리카노 20, 카페라떼 15, 바닐라라떼 10, 콜드브루 5, 자몽에이드 8, 딸기라떼 0

[요구사항 - 빠짐없이]
1. 재고 0 인 메뉴는 카드에 "품절" 배지를 표시하고 클릭해도 옵션 창이 열리지 않는다
2. 카드에 남은 재고 수를 표시한다 (재고 5 이하일 때만 "5개 남음" 형태로)
3. 장바구니에 담긴 수량만큼 가용 재고가 줄어든다 (표시에 즉시 반영)
4. 가용 재고를 초과해 담으려 하면 담기지 않고 "재고가 부족합니다" 안내를 띄운다
5. 장바구니에서 수량을 줄이거나 삭제하면 가용 재고가 즉시 돌아온다
6. 같은 메뉴는 옵션이 달라도 재고를 공유한다
   예: 아메리카노 재고 20 → Hot 3개 + Ice 2개 담으면 남은 재고 15
7. + 버튼도 가용 재고를 넘으면 눌리지 않는다 (비활성화)

[설계 제약]
- src/stock.js 를 새로 만들고 순수 함수만 넣는다
  getAvailable(menu, cart, menuId) -> 정수
  canAdd(menu, cart, menuId, qty) -> boolean
- DOM 접근 금지
- app.js 는 이 함수들을 호출만 한다

[금지]
- 쿠폰, 저장 기능 (아직 아님)

[개발환경]
conda 환경에 vscode가 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.

[테스트]
chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.
```

완료된 코드를 저장.
```bash
git save "feat: 재고와 품절 처리"
```

## 보호 경로 만들기

에이전트의 **전형적인 부정행위**를 구조로 막는다
`.claude/settings.json` 의 `deny` 에 추가합니다.
```json
{
  "permissions": {
    "deny": [
      "Bash(git push --force*)",
      "Bash(rm -rf*)",
      "Edit(./expected/**)",
      "Write(./expected/**)",
      "Edit(./src/menu.js)"
    ]
  }
}
```

세션 재시작 후 일부러 시켜봅니다.
```prompt

src/menu.js 에서 콜드브루 재고를 100으로 바꿔 주세요.
```


bash deny만 남기고 나머지는 삭제.
완료된 코드를 저장.
```bash
git save "setting: deny 권한 설정"
```

## 쿠폰 기능으로 컨텍스트 자산 생각해 보기

내가 구현하려는 기능에 **애매한 부분은 없는지 AI와 대화 한다**.
```prompt
아래 요구사항을 구현하기에 애매한 부분을 핵심만 정리해 주세요.
그리고 정리된 핵심 내용을 해결할 방법을 가이드 해 주세요. 특히 쿠폰 적용 여부를 판단하는 경계부분에 대해 잘 정리해 주세요.

WELCOME10: 10% 할인, 최대 2000원
COFFEE1000: 1000원 할인, 10000원 이상 주문
SHOTFREE: 샷 추가 금액 전액 할인
```

herdr를 사용하는 경우 codex와 협업 하기.
```prompt
/herdr 오른쪽에 codex 패널을 만들고 아래 요구사항을 구현하기에 애매한 부분을 핵심만 정리해 주세요. 정리된 핵심 내용을 해결할 방법을 가이드 해 주세요. 특히 쿠폰 적용 여부를 판단하는 경계부분에 대해 잘 정리해 주세요.

WELCOME10: 10% 할인, 최대 2000원
COFFEE1000: 1000원 할인, 10000원 이상 주문
SHOTFREE: 샷 추가 금액 전액 할인
```

직접 만들 경우 아래 프롬프트와 비슷하게 물어 본다.
```prompt
내가 직접 개발 프롬프트를 작성할 예정입니다. 위 결과를 기반으로 내가 만든 프롬프트에서 반드시 체크해야 할 체크 리스트를 만들어 주세요.
```

AI의 조언을 보면서 직접 프롬프트를 만듭니다.
```prompt
[목표]
쿠폰 기능을 만들어 주세요.

[쿠폰 목록]
- WELCOME10 : 할인 전 합계의 10% 할인, 최대 2,000원
- COFFEE1000 : 1,000원 할인. 할인 전 합계가 10,000원 이상일 때만
- SHOTFREE : 장바구니 전체의 샷 추가 금액 전액 할인. 샷이 1개 이상일 때만

[경계 규칙 - 반드시 이대로]
- 쿠폰은 한 번에 한 개만 적용된다. 새 코드를 입력하면 기존 것을 대체한다
- 10% 계산에서 소수점이 나오면 원 단위로 내림한다
- COFFEE1000 의 "10,000원 이상"은 정확히 10,000원도 포함한다
- 할인 기준 금액은 항상 "할인 전 합계"다
- 할인 후 결제 금액은 최소 1,000원. 그 아래로 내려가면 1,000원으로 고정한다
- 코드는 대소문자를 구분하지 않는다. 앞뒤 공백은 무시한다
- 없는 코드나 조건 미달이면 적용하지 않고 사유를 표시한다
  - 없는 코드: "사용할 수 없는 쿠폰입니다"
  - 조건 미달: "10,000원 이상 주문 시 사용 가능합니다" / "샷 추가 시 사용 가능합니다"

[화면]
- 장바구니 아래에 쿠폰 코드 입력칸과 [적용] 버튼
- 적용되면 "쿠폰 WELCOME10 적용 (-2,000원)" 표시와 [해제] 버튼
- 합계 영역: 상품 금액 / 할인 금액 / 결제 금액 3줄

[설계 제약]
- src/coupon.js 를 새로 만들고 순수 함수만
  applyCoupon(cart, code) -> { ok, discount, reason, code }
- DOM 접근 금지. 쿠폰 목록도 이 파일에 상수로
- app.js 는 호출만

[개발환경]
conda 환경에 vscode가 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.

[테스트]
chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.

작업 후 경계 케이스 확인 방법을 알려줘.
```

완료된 코드를 저장.
```bash
git save "feat: 쿠폰과 할인 규칙"
```

## CLAUDE.md 만들기

기존에 프로젝트를 vibe coding 할때 /init 으로 자동 생성이 가능.
먼저 자동으로 생성 테스트.
```command
/init
```

복구
```bash
git undof
```

```prompt
/herdr init 으로 기존 프로젝트를 분석해 CLAUDE.md를 만들어 주세요.

**순서**
1. 오른쪽 탭의 codex에게 프로젝트 심층 분석을 요청합니다. (harness engineering 공식 문서와 전문가 권고 검색 포함)
2. 응답을 기다리지 말고, 동시에 Claude도 같은 항목을 직접 분석합니다.
3. codex 결과가 오면 자체 분석과 대조해 통합한 뒤 CLAUDE.md를 작성합니다.

**작성 규칙**
- 50줄 이하, 한국어, 단정적이고 간결한 어조. 아래 4개 섹션만 사용합니다.
  1. 구조: 디렉터리와 파일별 역할 (테이블)
  2. 절대 규칙: 프로젝트 전체에 적용되는 금지 사항
  3. 비즈니스 규칙: 도메인 지식
  4. 검증: 테스트 및 검증 방법
- 특정 파일·경로에만 적용되는 규칙은 CLAUDE.md에 쓰지 않습니다. (`.claude/rules`에서 별도 관리)
- 모든 개발과 테스트는 conda 가상환경 `vscode`에서 실행합니다.
```


실제 실습을 위해 아래와 같은 CLAUDE.md를 직접 손으로 만들어 사용 합니다.
```markdown
# cafe-kiosk
브라우저에서 동작하는 카페 주문 키오스크. 서버·빌드도구·npm 패키지 없음.

## 프로젝트 구조
| 경로 | 책임 | 순수 함수 |
|---|---|:---:|
| `src/menu.js` | 메뉴·가격·재고 데이터. **변경 금지** | - |
| `src/cart.js` | 장바구니 계산 | ✅ |
| `src/coupon.js` | 쿠폰 규칙 | ✅ |
| `src/stock.js` | 재고 계산 | ✅ |
| `src/receipt.js` | 영수증 텍스트 생성 | ✅ |
| `src/storage.js` | localStorage 접근. **여기서만** | ❌ |
| `src/app.js` | DOM 렌더링·이벤트. **여기서만** | ❌ |

## 절대 규칙
- ✅ 표시 파일에서는 `document`, `window`, `localStorage`, `Date.now()` 사용 금지
- ✅ 표시 파일의 함수는 원본 인자를 변형하지 않고 새 객체를 반환한다
- 금액은 정수(원)만. 소수점 금지. 나눗셈 결과는 `Math.floor`
- 프레임워크·빌드도구·npm 패키지 추가 금지
- `src/menu.js` 와 `expected/` 는 수정하지 않는다

## 비즈니스 규칙
- 같은 메뉴라도 옵션이 다르면 장바구니에서 별도 줄
- 같은 메뉴는 옵션이 달라도 재고를 공유한다
- 자몽에이드: Hot 불가, 샷 추가 불가
- 쿠폰은 한 번에 하나만. 새 코드는 기존 것을 대체
- 할인 기준은 항상 할인 전 합계
- 할인 후 결제 금액 최소 1,000원

## 환경과 검증
conda 환경에 vscode 가상환경이 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.
변경 후에는 항상 `make verify` 를 실행한다. 이게 유일한 검증 경로다.
화면이 바뀌는 변경은 chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.
```

실제 실습을 위해 아래와 같이 경로별 규칙 분리 파일을 만듭니다.

`.claude/rules/pure.md`:
```markdown
---
paths:
  - "src/cart.js"
  - "src/stock.js"
  - "src/coupon.js"
---

# 순수 함수 모듈 규칙

이 파일들의 모든 함수는 순수 함수여야 한다.

## 금지
- `document`, `window`, `localStorage`, `sessionStorage`
- `Date.now()`, `new Date()`, `Math.random()`
- `console.log` (디버깅 후 반드시 제거)
- 인자로 받은 객체·배열을 직접 수정하는 것

## 필수
- 현재 시각이 필요하면 함수 인자로 받는다
- 항상 새 객체/배열을 반환한다 (spread, map, filter 활용)
- 금액 계산에서 나눗셈이 생기면 `Math.floor` 로 마감한다
- 모든 export 함수는 대응하는 테스트가 `tests/` 에 있어야 한다
```

`.claude/rules/ui.md`:
```markdown
---
paths:
  - "src/app.js"
---

# UI 레이어 규칙

- DOM 렌더링과 이벤트 처리는 이 파일에서만 담당한다.
- 재고·가격·쿠폰 계산은 `stock.js`, `cart.js`, `coupon.js`의 함수를 호출해서 쓰고, 이 파일에서 같은 로직을 다시 구현하지 않는다.
- 전역 상태(`cart`, `currentCategory`, `appliedCoupon`)는 이 파일에서만 직접 변경한다.
```

완료된 코드를 저장.
```bash
git save "chore: 컨텍스트 자산 harness 기본 구축"
```
