# 계획 후 개발 프로세스
계획을 사람이 읽고 승인하는 이 한 단계가 가장 저렴하고 확실한 안전장치(Application Harnes) 입니다.

## **plan 모드**: 읽기만 하고 계획을 세운 뒤, 사람의 승인을 받고 실행한다

**방법 A** — `Shift+Tab` 을 눌러 권한 모드를 순환시키다가 **plan** 에서 멈춤
**방법 B** — 명령으로 바로 진입
```command
/plan
```

**프롬프트** (plan 모드에서)
```prompt
[목표]
카페 키오스크의 첫 화면을 만들 계획을 세워주세요.

[이번에 만들 것 — 이것만]
- 메뉴 6개를 카드 형태로 표시
- 카테고리 탭: 커피 / 논커피. 탭을 누르면 해당 메뉴만 표시
- 각 카드에 메뉴명과 가격(3,000원 형식)
- 클릭해도 아직 아무 일도 일어나지 않아도 됨

[이번에 만들지 말 것]
- 장바구니, 옵션, 쿠폰, 저장, 주문 — 전부 나중에

[제약]
- HTML + CSS + 순수 JS. 프레임워크·빌드도구·npm 금지
- 파일 구조는 index.html / styles.css / src/menu.js / src/app.js
- 메뉴 데이터는 src/menu.js 에 배열로 분리. 화면 코드와 섞지 않습니다.
- 금액은 정수. 표시할 때만 천단위 콤마

[개발환경]
conda 환경에 vscode가 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.

[테스트]
chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.

[원하는 것]
이걸 만들 때 내가 결정해줘야 할 애매한 지점을 질문 형태로 최대 5개 정리해 주세요.
계획이 완료되면 파일별 책임과 작업 순서를 계획으로 제시해 주세요.
작업이 끝났을 때 내가 브라우저에서 무엇을 보고 성공을 확인할 수 있는지도 알려주세요.
```

계획을 **읽고** 승인합니다. 마음에 안 들면 승인하지 말고 수정을 요구하세요.
추가 수정 요구 예제.
```prompt
추가적으로 더 결정해야할 사항이 있으면 최대 5개 정리해 주세요.
```

서버 실행하여 정상 동작되는 것 확인 후 git 커밋.
```bash
git save "feat: F1 메뉴 목록과 카테고리 탭"
```

## 실행 중간에 중단하고 방향 틀기
엉뚱한 방향이면 **끝까지 기다리지 않고 즉시 개입**한다

##### 1. 시작 프롬프트 프롬프트
```prompt
[목표]
메뉴 카드에 이미지 영역, 설명 문구, 인기 배지를 추가해 주세요.

[개발환경]
conda 환경에 vscode가 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.

[테스트]
chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.
```

##### 2. 작업이 시작되면 **3초쯤 뒤 `Esc`** 를 눌러 중단하고 바로 목표 수정:
```prompt
[목표]
설명 문구 추가해 주세요.
```

##### 3. 이어서 Claude가 작업하는 **중간에** 다음 문장을 미리 타이핑해 둡니다 (엔터까지).
```prompt
끝나면 변경한 파일 목록을 알려주세요.
```

테스트 였기 때문에 되돌림
```bash
git undof
```

##  모델과 추론 깊이 조절하기
작업 난이도에 따라 **모델과 추론 깊이**를 바꿀 수 있다

모델 변경
```command
/model
```
피커에서 모델 목록을 봅니다. 행 위에서 `s` 를 누르면 **이번 세션에만** 적용됩니다.

추론 깊이 확인
```command
/effort status
```

##### 1. 쉬운 작업은 낮게
```command
/effort low
```

쉬운 작업 프롬프트 실행
```prompt
[목표]
index.html 의 <title> 을 "녹천 카페 키오스크" 로 바꿔 주세요.

[개발환경]
conda 환경에 vscode가 있습니다. 개발 및 테스트는 모두 여기서 이루어 져야 합니다.

[테스트]
chrome extension을 이용하여 실제 브라우저에서 동작을 테스트 해 주세요.
```

##### 2. 어려운 작업은 높게
```command
/effort high
```

어려운 작업 프롬프트 실행
```prompt
앞으로 만들 장바구니 기능에서, 같은 메뉴라도 옵션(온도/샷/사이즈)이 다르면 별도 줄로 관리해야 합니다.

이때 장바구니 항목을 식별하는 키를 어떻게 설계해야 할까요?
- 옵션 조합이 늘어나도 안전한가?
- 수량 변경·삭제 시 정확히 그 줄만 찾을 수 있는가?
- 나중에 localStorage 에 저장했다 복원할 때 문제없나?

코드는 쓰지 말고 설계안 2가지를 비교해 주세요.
```

테스트 였기 때문에 되돌림
```bash
git undo
```

##  세션 다루기
대화를 **오염시키지 않고** 곁가지 질문을 한다

#### btw(by the way)
방금 까지의 대화가 복사되어 있는지 직전 작업의 설계안 2가지 중에 하나에 대해 물어 본다.
```prompt
/btw CSS Grid 와 Flexbox 의 차이와 현재 UI 레이아웃에 뭐가 나은지 짧게 설명해줘.
```
답을 듣고 나서 `/btw` 를 다시 치면 이전 곁가지 답을 볼 수 있습니다.


#### branch

현재 세션의 이름을 정해 둔다. 다시 돌아 올때 정확하게 돌아오기 위해.
```command
/rename 키호스크-메인작업
```

새로운 대화의 갈래를 만든다. 대화 복사본을 만들고 내가 그쪽으로 이동.
```command
/branch 설계안B
```

방금 까지의 대화가 복사되어 있는지 직전 작업의 설계안 2가지 중에 하나에 대해 물어 본다.
```prompt
방금 비교요약한 안 중에 B가 좋아 보이는데 B안에 대해 다시 이야기 해 주세요.
```

원래 세션으로 돌아가기
```command
/resume
```
